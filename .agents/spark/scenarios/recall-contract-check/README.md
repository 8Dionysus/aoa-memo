# Spark Scenario: recall-contract-check

Use `recall-contract-check` to inspect recall, retention, checkpoint,
adoption, recurrence, or writeback contracts for temporal and provenance
clarity.

## Scope

Read one recall-facing contract, object example, mechanic part, source map, or
generated companion. Small fixes are allowed only when the user asked for
check plus repair and the owner route is clear.

## Done Signal

The recall claim, source, temporal posture, salience limit, and validator route
are explicit, or the missing contract surface is routed to the next owner.

## Stop-line

Do not turn a recall contract into proof of current truth, identity, role
right, dispatch authority, live runtime state, or KAG ownership.

## Handoff Route

Write a handoff when the check finds a missing source contract, unclear
stronger owner, or runtime/proof/role boundary risk.

## Validation

Use `python scripts/validate_memory_surfaces.py` or the named mechanic-local
validator when the contract is mechanic-local.
