# Spark Scenario: memory-refinement

Use `memory-refinement` for one small source-backed patch to an existing
memory surface.

## Scope

Change one memory doctrine paragraph, object profile detail, schema/example
alignment point, mechanic-local route note, or compact index wording. The
source owner must already be clear before editing.

## Done Signal

One existing memory surface is more explicit, provenance-aware, temporally
honest, and bounded, with the narrow validation route named and run when
relevant.

## Stop-line

Stop when the patch asks for proof, route policy, role authority, KAG meaning,
runtime state, sibling-owner truth, or a second owner.

## Handoff Route

Write a handoff when the improvement needs broader doctrine, mechanic
redesign, generated-source migration, or cross-repo owner judgment.

## Validation

Run `git diff --check` plus the nearest source validator named by the touched
surface.
