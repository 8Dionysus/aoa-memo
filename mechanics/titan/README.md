# Titan Memo Mechanic

Titan is the memo-side mechanic for preserving recall candidates, remembrance
source refs, memory loom posture, audit memory policy, bridge and console
digests, closeout memory posture, personality memory policy, and swarm memory
policy without granting stronger authority.

## Mechanic card

- Status: `landed`

### Trigger

Use when Titan memory posture, recall candidates, remembrance source refs,
audit memory candidates, bridge/console digest posture, closeout proposals,
personality memory policy, or swarm memory policy must become explicit and
reviewable.

### Memo owns

Memo owns the public, source-linked memory shape: recall candidate fields,
source-ref posture, uncertainty, review requirements, digest boundaries,
closeout memory proposals, and stop-lines.

### Stronger owner split

- `aoa-agents` owns Titan role authority, actor rights, and write authority.
- `aoa-evals` owns proof and audit verdicts.
- `abyss-stack` owns runtime storage, private retention, and live memory
  machinery.
- Source repositories own authored source truth and owner-repo Titan doctrine.
- `aoa-routing` owns dispatch behavior when Titan memory becomes route input.

### Inputs

Reviewed source refs, recall candidate proposals, remembrance records,
audit-memory candidates, bridge or console digest notes, closeout memory
proposals, and owner confirmations.

### Outputs

Bounded Titan memo docs, schema/example source refs, test-backed candidate
contracts, and owner handoff routes.

### Must not claim

- memory was durably written
- a role right was granted
- an audit finding has proof status
- private or sensitive data can be retained without explicit approval
- `aoa-memo` owns Titan source doctrine

### Validation

Use the validation lane in [AGENTS](AGENTS.md#validation).

### Next route

Route role authority to `aoa-agents`, proof to `aoa-evals`, runtime storage to
`abyss-stack`, route behavior to `aoa-routing`, and authored source doctrine
to the owning source repository.
