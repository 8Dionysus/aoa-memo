# Questbook Memo Mechanic

Questbook is the memo-side mechanic for public, durable memory-layer
obligations. It keeps recall, writeback, recurrence, and adoption follow-up
visible without becoming a second roadmap, proof ledger, runtime state, or
private scratchpad.

## Mechanic card

- Status: `landed`

### Operation

preserve memo-facing obligations as public lane-first quest sources with owner-routed lifecycle and generated projections without becoming source quest state, proof, route dispatch, playbook choreography, runtime state, or hidden memory

### Trigger

Use when a memo-facing obligation must survive the current diff as a public,
reviewable follow-through item.

### Memo owns

Memo owns the public obligation shape, root index posture, lane-first source
placement, source contract, lifecycle validation, generated quest catalog, and
memo-side owner-routing stop-lines.

### Stronger owner split

- `Agents-of-Abyss` owns center questbook doctrine and source Agon meaning.
- `aoa-playbooks` owns scenario, campaign, and questline choreography.
- `aoa-evals` owns proof and closure-quality verdicts.
- `aoa-routing` owns dispatch and navigation behavior.
- `aoa-agents` owns role rights and agent authority.
- `abyss-stack` owns runtime scheduling, storage, and live state.
- Source owner repositories own acceptance, closure, and implementation truth.

### Inputs

Reviewed obligation notes, memo writeback follow-through, recall candidates,
owner-routed Agon follow-through, recurrence or checkpoint carry hints, and
source refs that need public memory-layer tracking.

### Outputs

Root `QUESTBOOK.md` index updates, `quests/<lane>/<state>/` source files,
generated quest catalog and dispatch projections, owner-routed next actions,
and public stop-lines.

### Must not claim

- source quest ownership
- proof or closure verdict
- playbook scenario state
- route dispatch
- runtime scheduling or live retention
- role rights or actor authority
- private scratch memory
- automatic owner acceptance

### Validation

Use the validation lane in [AGENTS](AGENTS.md#validation).

### Next route

Route source quest doctrine to `Agents-of-Abyss`, scenarios to
`aoa-playbooks`, proof to `aoa-evals`, dispatch to `aoa-routing`, role rights
to `aoa-agents`, runtime to `abyss-stack`, and owner-local acceptance to the
owning repository.

## Owner Boundary

Questbook keeps memory-layer obligations reviewable. It never makes memory the
owner of source quest state, proof, runtime, route dispatch, playbook
choreography, role authority, or owner acceptance.

## Growth Posture

Future questbook work should converge toward the Agents-of-Abyss questbook
shape when it improves memo recall without importing center authority.
