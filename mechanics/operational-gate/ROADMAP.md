# Operational Gate Roadmap

## Next

- Keep the four active gate docs aligned with root schemas, examples, tests,
  mechanics index, and AGENTS mesh.
- Add stricter machine checks for evidence refs, owner routes, and future
  effect fields only when repeated operational incidents prove a stable shape.
- Keep deployment incident, service revision, and post-release boundary
  examples public-safe and explicit about memory-not-proof posture.

## Not Yet

- Do not turn operational gate into a release authority surface.
- Do not make service revision ledger entries stand in for live runtime state.
- Do not move retention outcome docs out of the retention mechanic unless the
  operation changes from retention evidence to admission gating.
- Do not move writeback ledgers out of the writeback mechanic unless the
  operation changes from owner return to memory admission.
- Do not create package-local schemas or examples until artifact topology shows
  the public root technical lane is no longer the right owner.
