# Operational Gate Direction

## Current

Keep operational memory usable for OS Abyss by admitting only material,
evidence-linked, owner-routed events into durable recall.

## Operating Contour

- require evidence refs before an operational event becomes memory
- require an owner route before memory implies any future consequence
- distinguish admission gate, retention outcome, writeback return, and runtime
  execution
- keep service revision entries reviewable without treating them as live state
- keep post-release memory boundaries separate from release approval
- preserve expiry, recheck, or recurrence posture when an event is too weak for
  durable memory
- update schemas, examples, tests, and generated companions when active gate
  paths or contract expectations move

## Stop-Line

If a change needs live deployment, rollback, service remediation, eval proof,
assistant/service rights, route dispatch, release choreography, stats truth, or
source doctrine, route away before expanding this mechanic.
