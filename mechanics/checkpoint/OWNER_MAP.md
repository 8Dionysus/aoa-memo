# Checkpoint Owner Map

## Memo Owns

`aoa-memo` owns checkpoint memory shape:

- checkpoint support schemas and examples
- checkpoint approval and health memory examples
- checkpoint improvement provenance threads
- checkpoint-to-memory mapping into existing object kinds
- carry and return-pack recall posture
- stop-lines that keep checkpoint memory weaker than execution, proof, route,
  role, runtime, and source acceptance

## Stronger Owners

| Owner | Owns |
|---|---|
| `Agents-of-Abyss` | checkpoint doctrine, center law, and program meaning |
| `aoa-agents` | actor rights, checkpoint authority, handoff permission, and role policy |
| `aoa-playbooks` | checkpoint play, scenario choreography, and reviewed run meaning |
| `aoa-sdk` | dispatch, route compression, return navigation, and tier policy |
| `abyss-stack` | live checkpoint workers, runtime stores, retry loops, and checkpoint logs |
| `aoa-evals` | proof, score, quality verdicts, and regression gates |
| source owner repositories | acceptance of the checkpoint consequence |

## Interface Rule

Memo may preserve that a checkpoint artifact exists and how it maps into
memory. Memo may not decide that the checkpoint authorizes action.
