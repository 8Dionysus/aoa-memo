# Readiness Boundary Provenance

Readiness-boundary surfaces previously lived across `docs/`, root `schemas/`,
root `examples/`, and root `tests/`.

That shape was useful while the boundary was a small wave-one note. It became
too flat once the repository started moving mechanic-owned technical artifacts
beside their operation owner.

## Active Placement

- `mechanics/readiness-boundary/docs/` owns readiness-boundary doctrine.
- `mechanics/readiness-boundary/schemas/` owns the boundary contract schema.
- `mechanics/readiness-boundary/examples/` owns the boundary contract example.
- `mechanics/readiness-boundary/tests/` owns readiness-boundary mechanic tests.

## Former Placement

Former active paths now route here:

- `docs/MEMORY_READINESS_BOUNDARY.md`
- `schemas/memory_readiness_boundary_contract.schema.json`
- `examples/memory_readiness_boundary_contract.example.json`
- `tests/test_wave1_boundary_contract.py`

## Boundary Note

Root memory doctrine still owns the memory object canon. Readiness-boundary
owns the operation that admits or refuses high-pressure memory pressure before
stronger owners make proof, runtime, graph, route, role, scenario, or source
claims.
