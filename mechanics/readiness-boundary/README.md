# Readiness Boundary Memo Mechanic

Readiness-boundary is the memo-side mechanic for gating high-pressure memory
questions before they inflate into proof, runtime state, graph substrate,
route dispatch, role authority, or new object families.

## Mechanic card

- Status: `landed`

### Operation

gate high-pressure memory readiness pressure into existing memory objects and owner routes without becoming proof, runtime retention, graph substrate, route dispatch, role authority, live ledger, or new object-family author

### Trigger

Use when durable consequence, memory delta, canon delta reference, retention
pressure, unresolved contradiction, bridge candidate, service trace, or future
scar/survivor language needs memo-side admission posture before a stronger
owner accepts it.

### Memo owns

Memo owns the readiness pressure map, the boundary contract, reviewed example
shape, source refs, owner routing hints, and stop-lines that keep high-pressure
memory questions bounded to existing memory objects.

### Stronger owner split

- `Agents-of-Abyss` owns center-level protocol posture and ecosystem meaning.
- `aoa-evals` owns proof, score, verdict meaning, and promotion evidence.
- `abyss-stack` owns live stores, runtime retention jobs, backups, and local
  execution plumbing.
- `aoa-kag` owns downstream substrate lifts and graph normalization.
- `aoa-routing` owns route dispatch, navigation hints, and return policy.
- `aoa-agents` owns actor rights, role authority, and service contract meaning.
- `aoa-playbooks` owns scenario choreography and campaign-shaped routes.
- Source owner repositories own acceptance of durable consequences.

### Inputs

High-pressure memory refs, reviewed memory objects, bounded recall candidates,
memory delta refs, canon delta refs, retention pressure, contradiction refs,
bridge candidates, service traces, and owner feedback that a pressure surface
is overclaiming.

### Outputs

Readiness-boundary docs, boundary contract schema/example, existing-object
landing guidance, owner-routed next claims, generated object-surface refs, and
validator requirements.

### Must not claim

- proof, scoring, or verdict authority
- live memory ledger or runtime retention execution
- role rights, route dispatch, or scenario acceptance
- KAG graph normalization or Tree-of-Sophia canon authorship
- new `scar`, `readiness`, `survivor`, or `checkpoint_memory` object families
- source-owner acceptance or current truth by implication

### Validation

Use the validation lane in [AGENTS](AGENTS.md#validation).

### Next route

Route proof to `aoa-evals`, runtime retention to `abyss-stack`, graph lift to
`aoa-kag`, routing behavior to `aoa-routing`, actor/service rights to
`aoa-agents`, scenario meaning to `aoa-playbooks`, center doctrine to
`Agents-of-Abyss`, and source acceptance to the owning repository.
