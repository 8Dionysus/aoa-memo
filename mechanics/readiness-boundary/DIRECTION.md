# Readiness Boundary Direction

Readiness-boundary keeps high-pressure memory questions reviewable before
they become larger programs.

## Current Direction

- Keep readiness pressure mapped to existing memory objects before inventing
  new object families.
- Keep memory deltas distinct from canon delta refs.
- Keep retention pressure visible while runtime retention remains outside
  `aoa-memo`.
- Keep proof, graph lift, route dispatch, role authority, scenario acceptance,
  and source-owner acceptance with stronger owners.
- Keep the boundary contract package-local and validator-backed.

## Stop Lines

- No live memory ledger in `aoa-memo`.
- No runtime retention worker.
- No proof or verdict logic.
- No graph substrate ownership.
- No route or role authority.
- No new `scar`, `survivor`, or `readiness` memory-object kind.
