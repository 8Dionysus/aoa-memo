# Readiness Boundary Owner Map

## Memo Owns

`aoa-memo` owns readiness-boundary memory shape:

- readiness pressure map
- boundary contract schema and example
- memo-side admission and rejection language
- existing-object landing guidance
- owner-routed next claims
- stop-lines that keep readiness pressure weaker than proof, runtime, graph,
  route, role, scenario, and source acceptance

## Stronger Owners

| Owner | Owns |
|---|---|
| `Agents-of-Abyss` | center-level protocol posture and ecosystem meaning |
| `aoa-evals` | proof, score, verdict meaning, and promotion evidence |
| `abyss-stack` | live stores, runtime retention jobs, backups, and local execution plumbing |
| `aoa-kag` | graph-ready substrate lifts and normalization |
| `aoa-sdk` | route dispatch, navigation hints, and return policy |
| `aoa-agents` | actor rights, role authority, and service contract meaning |
| `aoa-playbooks` | scenario choreography and campaign-shaped routes |
| source owner repositories | acceptance of durable consequences or current truth |

## Interface Rule

Memo may preserve that a readiness pressure exists and how it maps into
memory. Memo may not decide that the pressure is proven, executable, current,
or accepted.
