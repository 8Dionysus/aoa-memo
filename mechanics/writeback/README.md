# Writeback Mechanic

Writeback is the memo-side mechanic for preserving source-linked writeback
maps and contracts without becoming runtime storage, a live receipt ledger, or
automatic promotion authority.

## Mechanic card

- Status: `landed`

### Operation

return bounded writeback targets, intakes, chronicles, revisions, rollback memories, and growth notes to owner routes without becoming live storage

### Trigger

Use when runtime writeback, quest or chronicle writeback, revision ledgers,
rollback writeback, growth return, self-agency continuity, A2A child return, or
writeback temperature must become reviewable memory-layer posture.

### Memo owns

Memo owns writeback source maps, intake descriptions, candidate-only posture,
review requirements, and generated companions that summarize memo-owned
writeback contracts.

### Stronger owner split

- `abyss-stack` owns live runtime storage, jobs, workers, and retention
  execution.
- `aoa-agents` owns actor rights and handoff authority.
- `aoa-playbooks` owns recurring scenario choreography and quest execution.
- `aoa-evals` owns proof and regression verdicts.
- `aoa-sdk` owns dispatch behavior.
- Source repositories own authored meaning and operational truth.

### Inputs

Source refs, writeback candidates, target maps, intake contracts, chronicle
events, revision notes, rollback memories, and growth-refinery handoff needs.

### Outputs

Bounded writeback docs, generated target or intake companions, candidate-only
memory routes, and owner handoff notes.

### Must not claim

- live writeback occurred
- runtime storage or background workers exist inside `aoa-memo`
- a promotion, role right, proof verdict, or owner acceptance has landed
- generated companions are stronger than source docs and builders

### Validation

Use the validation lane in [AGENTS](AGENTS.md#validation).

### Next route

Route runtime work to `abyss-stack`, role rights to `aoa-agents`, recurring
scenario work to `aoa-playbooks`, proof to `aoa-evals`, and dispatch behavior
to `aoa-sdk`.
