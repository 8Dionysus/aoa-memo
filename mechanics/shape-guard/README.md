# Shape Guard Memo Mechanic

Shape guard is the memo-side mechanic for pruning memory-object and
mechanic-shape inflation before new recall forms pretend to be proof, current
health, action authority, or owner acceptance.

## Mechanic card

- Status: `landed`

### Operation

prune memory-object and mechanic-shape inflation before new recall forms pretend to be proof, health, or action authority

### Trigger

Use when a new memory object family, mechanic package, trust field, recall
surface, or action-facing memory route is proposed and the repository needs to
ask whether an existing reviewed recall object, owner route, eval proof lane,
or runtime surface already fits better.

### Memo owns

Memo owns shape review questions, via-negativa pruning posture, duplicate
family detection, trust-collapse warnings, and owner-routed stop-lines for new
memory or mechanic forms.

### Stronger owner split

- `docs/MEMORY_MODEL.md`, `docs/MEMORY_OBJECT_PROFILES.md`,
  `docs/MEMORY_TRUST_POSTURE.md`, and `docs/LIFECYCLE.md` own the active memory
  object canon.
- Mechanic package cards own package-local operation, owner split, and docs.
- `aoa-evals` owns proof and bounded verdicts.
- `aoa-routing` owns dispatch behavior.
- `aoa-agents` owns role rights and action authority.
- `aoa-kag` owns graph substrate promotion.
- `abyss-stack` owns live runtime storage and execution.
- Source repositories own local meaning and adoption.

### Inputs

New memory object proposals, mechanic-package candidates, trust or confidence
field changes, recall-family additions, action-trigger claims, owner-route
pressure, and validator gaps.

### Outputs

Review questions, keep/merge/move/suppress/quarantine/deprecate/remove
recommendations, owner-route stop-lines, validator requirements, and bounded
shape decisions.

### Must not claim

- a memory object is proof
- current health has been certified
- an action may execute without owner receipts or eval backing
- a duplicate object family is justified by naming alone
- pruning has deleted owner truth or runtime state
- `aoa-memo` may replace a stronger owner surface

### Validation

Use the validation lane in [AGENTS](AGENTS.md#validation).

### Next route

Route object-canon changes to the root memory doctrine surfaces, proof to
`aoa-evals`, dispatch behavior to `aoa-routing`, role or action authority to
`aoa-agents`, graph promotion to `aoa-kag`, runtime execution to `abyss-stack`,
and source adoption to the source owner repository.
