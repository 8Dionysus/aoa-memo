# Lineage Harvest Memo Mechanic

Lineage harvest is the memo-side mechanic for gating cross-repo recurring
signals into reviewed pattern-lineage memory candidates and downstream dossier
boundaries so OS Abyss can remember repeated lessons without making
`aoa-memo` the federation authority, proof layer, KAG promoter, ToS canon,
stats judge, runtime watchtower, or source owner.

## Mechanic card

- Status: `landed`

### Operation

gate cross-repo recurring owner-local signals into reviewed pattern-lineage memory candidates and downstream dossier boundaries without making memo the federation authority, proof layer, KAG promoter, ToS canon, stats judge, runtime watchtower, or source owner

### Trigger

Use when owner-local receipts, bounded eval verdicts, watchtower incidents,
retention outcomes, route landings, or repeated cross-repo evidence suggest a
shared pattern candidate that needs lineage memory and stronger-owner gates
before any promotion, adoption, KAG lift, or ToS candidate dossier.

### Memo owns

Memo owns pattern-lineage memory posture, candidate-record shape, evidence-ref
requirements, owner-route requirements, lineage and supersession notes,
harvest-gate memory, downstream dossier boundary hints, and stop-lines that
keep repeated-pattern recall weaker than proof, promotion, adoption, source
truth, or canon.

### Stronger owner split

- `Agents-of-Abyss` owns federation harvest program law, center route meaning,
  and governance posture.
- Source repositories own local evidence, source truth, owner consent, and
  owner-local adoption.
- `aoa-evals` owns bounded verdicts, proof, scoring, and promotion evidence.
- `aoa-stats` owns recurrence summaries and movement reporting, not pattern
  certification.
- `aoa-kag` owns derived graph substrate formation and KAG promotion intake
  after memo, evidence, retention, and owner gates.
- `Tree-of-Sophia` owns authored meaning and canon intake; this mechanic never
  grants direct writes.
- `aoa-routing` owns dispatch behavior and owner-landing policy.
- `aoa-agents` owns role rights, assistant adoption posture, and self-rewrite
  stop-lines.
- `aoa-playbooks` owns owner-local adoption quests and campaign choreography.
- `abyss-stack` owns runtime watchtower incidents, live stores, and execution.

### Inputs

Owner-local receipts, source-owner evidence refs, bounded eval verdicts,
watchtower incident refs, memory retention outcomes, routing owner-landings,
cross-repo recurrence signals, federation pattern candidates, shared lesson
drafts, existing lineage or supersession records, and stronger-owner feedback
that a candidate is overclaiming.

### Outputs

Reviewable pattern-lineage memory candidates, owner-local landing hints,
harvest-gate decision memory, derived summary boundaries, KAG promotion dossier
hints where permitted, ToS candidate dossier boundary notes where permitted,
schema/example ref updates, and validation requirements.

### Must not claim

- federation harvest approval
- proof, score, or bounded verdict
- source-owner consent or local adoption
- KAG promotion or graph substrate truth
- Tree-of-Sophia canonization or direct ToS write permission
- recurrence certification by `aoa-stats`
- assistant or agent self-rewrite
- runtime watchtower truth, incident cause, or execution
- owner-local adoption quest completion

### Validation

Use the validation lane in [AGENTS](AGENTS.md#validation).

### Next route

Route federation program law to `Agents-of-Abyss`, source truth and adoption
consent to source repositories, proof to `aoa-evals`, recurrence summaries to
`aoa-stats`, derived graph promotion to `aoa-kag`, authored meaning to
`Tree-of-Sophia`, dispatch to `aoa-routing`, rights and assistant adoption
policy to `aoa-agents`, scenario/adoption choreography to `aoa-playbooks`, and
runtime watchtower execution to `abyss-stack`.

## Owner Boundary

Lineage harvest remains a memo mechanic until stronger owners decide
federation approval, proof, KAG promotion, ToS canon intake, runtime truth,
stats interpretation, or source-owner adoption. Memo can preserve the lineage
candidate and its gates; it cannot make the stronger claim.

## Growth Posture

Future work should tighten the pattern-lineage schema, example, and validators
only when repeated owner-local evidence proves a stable public contract. Do
not widen this package into governance decision authority, writeback execution,
retention execution, adoption approval, or graph platform behavior.
