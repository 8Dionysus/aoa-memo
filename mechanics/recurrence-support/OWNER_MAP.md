# Recurrence Support Owner Map

| Concern | Owner |
|---|---|
| Relaunch anchors, witness trace mapping into existing memory objects, reviewed closeout recall landings, source refs, and recurrence-support stop-lines | `aoa-memo` |
| Recurrence doctrine, center program law, and route-return meaning | `Agents-of-Abyss` |
| Actor identity, role rights, handoff permissions, freeze/promotion authority, and retry rights | `aoa-agents` |
| Scenario choreography, campaign return posture, and reviewed closeout play | `aoa-playbooks` |
| Dispatch behavior, route compression, tier escalation, and return navigation policy | `aoa-routing` |
| Live stores, checkpoint workers, runtime rebuild policy, retry loops, and return-event logging | `abyss-stack` or runtime owner |
| Proof, scoring, quality gates, adoption verdicts, and eval evidence weighting | `aoa-evals` |
| Owner acceptance of a recall candidate, return consequence, or source claim | the owning repository or source owner |

`aoa-memo` may preserve what helps a route return. It must not imply that the
return is authorized, proved, routed, retried, accepted, or currently true.
