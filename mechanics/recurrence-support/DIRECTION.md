# Recurrence Support Direction

## Current

Keep OS Abyss route-return memory usable by preserving compact, reviewable
relaunch support without making `aoa-memo` the route, runtime, role, proof, or
scenario owner.

## Operating Contour

- preserve bounded relaunch anchors and checkpoint continuity refs
- map witness traces into existing memory objects rather than inventing a new
  trace object family
- keep reviewed closeout recall landings owner-local and evidence-linked
- route recurrence doctrine, dispatch, retry policy, rights, proof, and
  scenario choreography to stronger owners
- keep inquiry checkpoint and witness trace schemas/examples package-local;
  keep only shared recall and quest companions in root districts
- update quests, generated surfaces, tests, and validators when active
  recurrence-support paths move

## Stop-Line

If a change needs route dispatch, retry budgets, runtime stores, role rights,
identity continuity, eval proof, scenario acceptance, or source-owner
acceptance, route away before expanding this mechanic.
