# Governance Memo Mechanic

Governance is the memo-side mechanic for preserving reviewable governance,
federation, installation, certification, precedent, stay-order, and
via-negativa memory boundaries without becoming authority, proof, runtime
governance, or source-owner consent.

## Mechanic card

- Status: `landed`

### Trigger

Use when governance route signals, federation harvest boundaries,
installation or certification memory gates, policy precedents, stay orders, or
via-negativa pruning rules must become explicit, source-linked, recallable, and
bounded.

### Memo owns

Memo owns governance memory posture, precedent recall, local-owner consent
reminders, authority-check fields, forgetting and expiry posture, and
owner-routed handoff language.

### Stronger owner split

- Source repositories own local meaning authority, evidence receipts, incident
  truth, and adoption consent.
- `Agents-of-Abyss` owns center governance, federation, release, and program
  law.
- `Tree-of-Sophia` owns authored meaning and never receives direct runtime or
  assistant writes from this mechanic.
- `aoa-evals` owns proof and bounded verdicts.
- `aoa-routing` owns dispatch behavior.
- `aoa-agents` owns role rights and assistant authority.
- `aoa-playbooks` owns scenario choreography and campaign cadence.
- `abyss-stack` owns runtime governance, live storage, and execution.

### Inputs

Governance route signals, owner-local evidence refs, decision refs, authority
checks, federation pattern candidates, installation/certification gates,
policy precedents, stay-order records, and pruning rules.

### Outputs

Bounded governance memory docs, precedent recall surfaces, authority-check
reminders, forgetting or expiry posture, and stronger-owner handoff routes.

### Must not claim

- a council, owner, release, or runtime decision has been made
- a policy precedent forces owner-local adoption
- a federation pattern has proof or KAG promotion status
- Tree-of-Sophia may be written directly
- assistant agents may self-recharter or self-promote
- `aoa-memo` owns live governance, release approval, or runtime authority

### Validation

Use the validation lane in [AGENTS](AGENTS.md#validation).

### Next route

Route center governance to `Agents-of-Abyss`, authored meaning to
`Tree-of-Sophia`, proof to `aoa-evals`, dispatch behavior to `aoa-routing`,
role authority to `aoa-agents`, scenario choreography to `aoa-playbooks`, and
runtime governance or execution to `abyss-stack`.
