# AGENTS.md

Root route card for `aoa-memo`. A nearer `AGENTS.md` supplies the local delta
for its subtree.

## Purpose and owner lane

`aoa-memo` is the explicit memory and recall layer of AoA. It owns memory-object
shape and classes, recall and salience posture, temporal relevance,
memory-temperature vocabulary, provenance and witness traces, reviewed
writeback, chronicle, recurrence-support, lineage-harvest seams, owner-local
statistics, and admitted memo-owner procedures.

Memory is not proof. Recall does not establish identity, agency, source truth,
runtime currentness, or live quest authority. Techniques, shared skills, eval
proof, routing, roles, playbook semantics, KAG substrate meaning, cross-owner
statistics, and runtime behavior remain with their owners.

## Authority and agent stack

- Root owns repository identity, owner boundaries, route choice, and the
  shortest honest verification path. The nearest nested card owns local risk,
  source routes, stop-lines, and validation routing only.
- Authored owner sources define meaning. Generated memory indexes, MCP results,
  exports, compact readers, runtime mirrors, and adapters remain weaker views.
- Change authored source or builder inputs before regenerated companions. A
  generated surface without a safe builder is owner debt, not permission for a
  hand edit.
- Keep self-agency, recurrence, quest, progression, checkpoint, and growth
  claims bounded, reversible, reviewable, and evidence-linked.

## Memory route and stop-lines

Use this repository when local candidates, reviewed session evidence, or MCP
recalls need durable object structure, lifecycle, provenance, consolidation,
or a reviewed handoff contract.

- Raw session evidence remains in `.aoa` and must be retrieved or reviewed
  through its owner route.
- Pre-review preservation belongs in the originating repository's `memo/`
  port when present.
- Reviewed durable objects here use the corpus object contract. Reviewed local
  exports enter only through the guarded intake route; a candidate or export
  is not already landed memory.
- `aoa_memo` MCP is an access plane. The reviewed repository corpus remains
  source truth, with temporal and provenance limits intact.

Route away when the task needs proof, execution logic, authored source
meaning, routing authority, role authority, or scenario composition. Stop when
memory wording is being used as current truth without explicit time and
provenance framing.

## Decision and Release route

After a structural, ownership, route-law, validator-authority, public-contract,
or topology change, use `docs/decisions/AGENTS.md` to determine whether future
agents need a durable rationale. Update only the roadmap, changelog, design,
memory index, stats, skills, root law, generated companions, mechanic ledgers,
or neighboring owner routes whose meaning actually changed.

The ordinary branch, PR, CI, merge-method, and post-merge procedure lives in
`docs/root/RELEASING.md`. If status, review, authority, or post-merge state
cannot be observed, stop and report the blocker rather than infer success.

## Validation and closeout

After the touched surface is known, use focused lanes through its
same-directory `VALIDATION.md`.
Each validation file owns one local route; reusable lane sequences remain
canonical in `config/validation_lanes.json`, with policy in
`docs/validation/COMMAND_AUTHORITY.md`. Do not recreate manifest-owned command
sequences across local validation cards.

Use the named release lane for the frozen owner gate. A missing required
external validator, including `aoa-stats`, is a failed check rather than a
skip. Local checks, release validation, CI, review, merge, publication,
runtime use, and owner acceptance remain distinct claims.

Closeout states the memory surface and class changed, provenance and temporal
effects, writeback/chronicle/recurrence/statistics seams, generated parity,
checks run and skipped, decision result, remaining risk, and next owner route.
